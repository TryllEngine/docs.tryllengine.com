# Generate and Speak

The Generate-and-Speak node fuses LLM token generation with streaming [TTS](https://docs.tryllengine.com/v0.9/reference/glossary.html#tts) synthesis: it runs the same projection and [language-model](https://docs.tryllengine.com/v0.9/reference/glossary.html#language-model) inference as a [Generate](https://docs.tryllengine.com/v0.9/reference/nodes/generate.html) node, but as tokens arrive it segments them into sentences, dispatches each sentence to a dedicated TTS strand, and emits PCM audio frames alongside the text deltas.

Because synthesis overlaps generation, audio begins after roughly the first sentence (`min_sentence_chars`) rather than after the whole answer — the TTS of one sentence runs while the LLM is still generating the next. This is the lowest-latency way to speak a generated answer (measured by the `time_to_first_audio_ms` diagnostic). `sampling.max_tokens` is fixed at creation, the same as on [Generate](https://docs.tryllengine.com/v0.9/reference/nodes/generate.html). Chaining a standalone [Generate](https://docs.tryllengine.com/v0.9/reference/nodes/generate.html) → [Speak](https://docs.tryllengine.com/v0.9/reference/nodes/speak.html) instead (with Speak's `input` set to the Generate node's output) produces the same voice but cannot start until generation has fully finished, since `Speak` only sees the completed text. Prefer this fused node when you want a generated answer spoken with minimal delay, and the split form only when you need to branch on, inspect, or transform the text in between.

The node has no voice settings. It speaks with the agent's [voice profile](https://docs.tryllengine.com/v0.9/reference/voice-profile.html), which you pass when you create the agent. A graph with a Generate and Speak node and no voice fails agent creation with `3025 AgentVoiceRequired`. The TTS model, speaker, speed, language, reference clip, delivery mode and `emit_visemes` all come from the profile. The node keeps its language-model settings and its chunking (`min_sentence_chars`, `first_chunk_max_chars`).

The audio format is announced once per turn, by the first speaking node that produces audio, so a later [Speak](https://docs.tryllengine.com/v0.9/reference/nodes/speak.html) node in the same turn reuses it. With the voice's `emit_visemes` on, the node sends one lip-sync viseme frame per sentence.

`NodeType`: `GenerateAndSpeak`.

Leave `context_size` at `0` to inherit the model variant's window, then the server `default_n_ctx` (commonly 8192) — the same resolution as [Generate](https://docs.tryllengine.com/v0.9/reference/nodes/generate.html). The `context` table is an advanced structural override. Do not set `q4_0` KV expecting a VRAM win at a right-sized window.

## Exits

Each exit is a structural string field on the node's params; its value names the target node (empty = END).

| Exit      | Param field    | Description                                                                                  |
| --------- | -------------- | -------------------------------------------------------------------------------------------- |
| `default` | `default_exit` | Default exit target — routes here after generation + synthesis complete. Empty string = END. |

LoRA adapters

`adaptation.loras` runs this node's model with one or more fine-tuned LoRA adapters, each with a scale. See [Use a LoRA Adapter](https://docs.tryllengine.com/v0.9/how-to/use-a-lora-adapter.html) for where to put the file and how to tune the scale.

## Constrained output (GBNF grammar)

Like [Generate](https://docs.tryllengine.com/v0.9/reference/nodes/generate.html#constrained-output-gbnf-grammar), this node accepts an optional `grammar` (GBNF) that constrains the generated output at every decode step. The full rules there apply verbatim (must contain a `root` rule; fail-fast at agent creation and `InvalidParamValue` 3007 on a bad mutation; mutable per turn; constrain the wire, not the thinking).

The fit here is **narrower** than on Generate: the constrained output is also *spoken*, so grammar only makes sense when the constrained text is itself meant to be voiced — e.g. restricting an NPC to a fixed set of barks or canned lines:

```
root ::= "Halt!" | "Who goes there?" | "Move along." | "For the throne!"
```

Note the interaction with `min_sentence_chars` (default 12): very short constrained output may never cross the sentence-boundary threshold, so the whole (tiny) output flushes as a single TTS call — which is fine for barks.

See [Concept: Constrained output (GBNF)](https://docs.tryllengine.com/v0.9/concepts/constrained-output.html) for what a grammar does and doesn't guarantee, and [How to constrain output with a grammar](https://docs.tryllengine.com/v0.9/how-to/constrain-output-with-a-grammar.html) for a worked example.

## Diagnostics

When `enable_diagnostics = true`, this node contributes to `debug_info.nodes[].diagnostics`. See [Turn Diagnostics JSON](https://docs.tryllengine.com/v0.9/reference/turn-diagnostics-json.html) for the envelope, the shared `input.prompt[]` shape, and the `engine` counters.

This is the only node that emits a fifth section, **`tts`** — the voice half of the fused step is kept separate from the language-model parameters. It holds the agent's [voice](https://docs.tryllengine.com/v0.9/reference/voice-profile.html#diagnostics) as it was when the node ran, plus this node's chunking.
