    Detailed Description¶

    Per-agent NodeEvent surfaces. No AgentId pin: the component is the agent. Session-level equivalents on UTryllSubsystem stay the "all agents" escape hatch. Actor component: manages one Tryll server-side agent. Attach to any Actor; Blueprint users bind to the delegates and call SendMessage().

    The graph comes from WorkflowAsset — a designer-authored data asset in the Content Browser. CreateAgent fails if no asset is assigned. To build a graph in C++ without an asset, use FTryllGraphBuilder and UTryllSubsystem::RequestCreateAgent.

    The component auto-creates an agent once the session is ready (if bAutoCreateOnConnect) — it queues until OnCreateSessionComplete if it spawns before the session is configured. It auto-destroys the agent on EndPlay.

    function FindToolHandler¶

    const FTryllToolHandler * UTryllAgentComponent::FindToolHandler (
    const FString & ToolName
) const

    Look up a registered tool handler without going through an agent, or nullptr when this component has none for that name. Lets an external driver that runs its own agent — the Dialog Lab — invoke the same game-side handler this component would have used, instead of simulating it with authored data.

    A handler that keeps per-conversation state must be told when the dialogue restarts, and such a driver's agent is not this component's, so none of the delegates here fire for it. The convention is a parameterless UFUNCTION() named ResetToolState on the handler's component, which the driver dispatches by name. The Chat panel and the Dialog Lab both run their own agent and dispatch it at each new conversation. In-game callers need nothing extra: the handler binds OnAgentReady and OnInteractionsRemoved itself.

    The returned pointer is owned by this component's handler map and is invalidated by RegisterTool / UnregisterTool. Call it, do not store it.

    function GetAgent¶

    function SendMessage¶

    void UTryllAgentComponent::SendMessage (
    const FString & Message
)

    Send a user-turn message to the agent. Streaming tokens arrive on OnAnswerText; the turn ends with OnTurnComplete + OnAnswerFull. No-op if the agent is not yet ready (IsAgentReady() == false).

    The message is queued, not dropped, when the agent exists but cannot accept it yet. An agent refuses a send with AgentBusy while a turn is running or a KV-cache operation is in flight — and a cache operation is exactly what happens when a game prefills the agent the player has just selected. Without queueing, a message typed during that window is silently lost and the player must retype it, which is the worst available outcome. The queue is flushed automatically when the agent becomes ready, when a turn completes, and when a cache operation finishes.

    Only the most recent message is held: if two are sent before either reaches the agent, the newer line is the one the player meant. OnMessageQueued fires when a send is deferred.

    function SetDeliveryMode¶

    void UTryllAgentComponent::SetDeliveryMode (
    const FString & Mode,
    float Intensity=1.f
)

    Switch the voice's delivery mode, e.g. "angry". Allowed mid-turn; applies from the next sentence. "neutral" always works; a mode the profile does not define fails with UnknownDeliveryMode (3024) and the current mode stays. Intensity (0..1) scales the mode where the model can (speed scale, Maya1 clause strength, Chatterbox expressiveness). OnDeliveryModeChanged reports the result.

    function TryFlushPendingMessage¶

    bool UTryllAgentComponent::TryFlushPendingMessage ()

    Hands the queued message to the agent if it can accept one now. Safe and cheap to call repeatedly; returns true only when a message was actually handed over.

    Called automatically on agent-ready, turn-complete and cache-operation-complete. It is public because a KV-residency policy that drives prefills through FTryllAgent directly — rather than through this component — closes a busy window this component never observed, and should nudge the queue when it does.
